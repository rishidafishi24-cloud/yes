# Build understanding first, then run REA safely

The bottom-up spine the learner planned (one request, then app layers, tools, MCP, memory and RAG, local internals, how models are made, then reverse engineering) is sound, and the notes recommend only four changes. First, move builder basics (terminal, JSON, environment variables, npx, git) from step 6 to just before tools and MCP, because the official MCP setup needs them. Second, swap local-model internals and "how models are made", so weights are understood before they are compressed and run. Third, thread security (prompt injection, permissions, supply chain) through every step instead of saving it for the end. Fourth, add a short "what an LLM is" step 0 and run Anthropic's free AI Fluency course alongside steps 1 to 3 to cover "use apps like a pro". The learner's Ryzen 5 2600 / 16 GB / RX 580 8 GB machine is not "cooked": LM Studio's Vulkan runtime runs it at about **39 tokens/s generation** on a 7B Q4 test, and the realistic models are 4B to 9B at Q4_K_M. Learning to code is worth a light, read-and-verify version only: the evidence favors reading, specifying and verifying code over writing it from scratch. The most urgent correction is a security misconception: `.env` and `.gitignore` do not encrypt anything. REA (a roughly 126-tool reverse-engineering MCP server, per the learner; the notes could not verify that count) should be used only on practice targets, in a VM, pinned to an exact version, with a cloud model rather than an 8B local one. Several claims in the notes remain unverified or conflict between sources; they are listed at the end.

## The planned order holds, with four evidence-backed changes

The notes compared the plan against how Anthropic, OpenAI, Hugging Face and the AI-literacy frameworks sequence material. All of them put using and understanding before designing and building. Anthropic's context-windows documentation moves from context to tools to memory and compaction, and OpenAI's Academy runs Foundations, then Applied Foundations, then Agents and Workflows, with the instruction "take them in this order" ([OpenAI Help Center](https://help.openai.com/sr-rs/articles/20001270-openai-academy-courses)). The frameworks themselves (AI4K12, the EC/OECD framework finalized in June 2026 with 19 competences, Elements of AI) do not prescribe a strict order and say nothing about MCP, local models or git, so the sequencing evidence for steps 3 to 7 comes from course structures and tool prerequisites, not from literacy research ([EdTech Innovation Hub](https://edtechinnovationhub.com/news/european-commission-and-oecd-set-19-ai-literacy-competences-for-schools)).

The first change is moving builder basics earlier. The official MCP local-server tutorial requires Node.js and npx, a hand-edited JSON config, absolute paths and an `env` block for keys ([MCP guide](https://modelcontextprotocol.io/docs/develop/connect-local-servers)), and Claude Code recommends Git for Windows ([Claude Code docs](https://code.claude.com/docs/en/overview)). A learner who cannot read JSON cannot configure REA or Higgsfield. The second change is swapping local internals and model-making: Karpathy's framing of an LLM as "a next-token predictor with two files" links training output directly to what a local runner loads ([BERI summary](https://www.beri.net/learning/karpathy-intro-to-llms)), and Karpathy himself teaches "Deep Dive" before "How I use LLMs". The third is threading safety: the MCP spec says tools "represent arbitrary code execution and must be treated with appropriate caution" ([MCP Specification](https://modelcontextprotocol.io/specification/latest)), so prompt-injection awareness belongs in the same step as the first MCP server. The fourth is hands-on from step 2, since LM Studio can be installed in minutes and fits a fast learner who dislikes clutter. The resulting path is: 0 what an LLM is; 1 one request; 2 app layers; 2.5 builder basics; 3 tools; 4 MCP, skills, plugins and Higgsfield; 5 memory and RAG; 6 how models are made; 7 local internals; 8 reverse engineering, then REA.

## Steps 0 to 2: what an LLM is, what one request does, and who is who

**Step 0 (first hour).** The key concept is that a model predicts the next token, and a token is a chunk of text. Watch 3Blue1Brown's short "LLMs explained briefly", then Karpathy's one-hour "Intro to Large Language Models" (no math or code needed), and paste text into Tiktokenizer to see tokens ([3Blue1Brown](https://3blue1brown.substack.com/p/large-language-models-explained-briefly); [BERI](https://www.beri.net/learning/karpathy-intro-to-llms)). Tiktokenizer shows OpenAI encodings, not Claude's tokenizer, so counts differ by model ([Lilly Tech guide](https://aischool.lillytechsystems.com/tiktokenizer/getting-started.html)).

**Step 1: one request, start to finish.** The core idea is that chat endpoints are stateless. OpenAI states that "each text generation request is independent and stateless" and that you resend earlier messages ([OpenAI](https://developers.openai.com/api/docs/guides/conversation-state)). Anthropic lists what counts toward the window: the system prompt, every message, tool results, images and tool definitions ([Anthropic](https://platform.claude.com/docs/en/build-with-claude/context-windows)). For this learner's stack, Odysseus builds a full messages array and POSTs it to LM Studio's `/chat/completions`, and LM Studio's OpenAI-compatible endpoint is stateless ([Odysseus source](https://raw.githubusercontent.com/pewdiepie-archdaemon/odysseus/main/src/llm_core.py); [LM Studio REST docs](https://lmstudio.ai/docs/developer/rest)). The three misconceptions to correct are that history lives in the weights, that an overflowing context is "compressed into memory", and that caching is memory. The model is a fixed function. The app keeps the transcript and decides what to trim or summarize. Odysseus compacts at 85% of the window by asking a model (by default the user's own local one) to summarize the older half, then drops the oldest turns if needed ([Odysseus compactor](https://raw.githubusercontent.com/pewdiepie-archdaemon/odysseus/main/src/context_compactor.py)). Chat templates matter here too: the app's message list is converted into one token stream with model-specific markers, and a wrong template or stop token makes a model print `<|im_end|>` or speak as the user ([Hugging Face](https://huggingface.co/docs/transformers/main/en/chat_templating)). LM Studio reads the template from the GGUF metadata automatically, and "in most cases you don't need to change" it ([LM Studio](https://lmstudio.ai/docs/app/advanced/prompt-template)). The KV cache and provider prompt caches are exact-prefix speed and price shortcuts. Anthropic says caching leaves the response "identical" ([Anthropic](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). The practical consequence on an RX 580 is that editing an old message, trimming or compacting changes the prompt's start and forces slow reprocessing. Best free resources are the Anthropic context-windows doc and the Karpathy "Intro" video.

**Step 2: app layers.** Separate the model (weights), the runner (LM Studio, llama.cpp), the app (Odysseus, Zed, Claude Code, Codex) and the provider (Anthropic, OpenAI, OpenRouter). The hands-on lab is to install LM Studio, load a small model, start its OpenAI-compatible server and point a second app at it. The LM Studio connection from Odysseus is not documented by Odysseus (its setup guide describes Ollama), so the notes infer `http://localhost:1234/v1` natively or `http://host.docker.internal:1234/v1` from Docker, and recommend testing it ([Odysseus setup guide](https://github.com/odysseus-dev/odysseus/blob/main/website/setup.md)). Odysseus's default for manually added endpoints is text-based fenced-block tool calling, not native structured calls, so a strong instruction-follower matters. Useful free resources are the LM Studio docs, Karpathy's "How I use LLMs", and Zed's AI docs. Anthropic's free "AI Fluency" and "AI capabilities and limitations" courses (about 4 and 3.5 hours) cover the "use apps like a pro" thread ([Claude Academy](https://academy.claude.com/)). Anthropic's prompt-engineering tutorial is dated, built on Claude 3 Haiku, so it is lower priority ([GitHub](https://github.com/anthropics/prompt-eng-interactive-tutorial)).

## Step 2.5: builder basics, and the secret-hygiene misconception

The learner already understands ports, APIs and terminals, but not JSON, git versus GitHub, `npm install`, `.env` or `.gitignore`. Each is an afternoon of learning. JSON is a strict text format: double quotes only, no trailing commas, no comments, and Claude Code's own `settings.json` raises a Settings Error on a stray comment ([MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/JSON); [Claude Code settings](https://code.claude.com/docs/en/settings)). Git is the undo-history program on your computer and GitHub is the website that stores copies and adds collaboration ([GitHub glossary](https://docs.github.com/en/get-started/learning-about-github/github-glossary)). The habit that matters most for agent users is committing before a big agent run, because Claude Code's checkpoints "aren't a replacement for git" and do not cover shell commands ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)).

The misconception to correct directly is that `.env` and `.gitignore` encrypt secrets. A `.env` file is plain text loaded into a program, and the dotenv README says not to commit it "unless you encrypt it with dotenvx" ([dotenv](https://github.com/motdotla/dotenv)). `.gitignore` only keeps untracked files untracked: "Files already tracked by Git are not affected" ([git-scm](https://git-scm.com/docs/gitignore)). AI agents can read `.env` unless a deny rule such as `Read(./.env)` is set ([Claude Code settings](https://code.claude.com/docs/en/settings)). If a key is pushed, GitHub's instruction is to revoke or rotate it first, because forks and clones keep copies ([GitHub Docs](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)). The scale is large: GitGuardian counted about **29 million** new hardcoded secrets on public GitHub in 2025 (up 34%), and found commits co-authored with Claude Code leaked at about twice the baseline rate, a correlational figure that may reflect who uses agents ([GitGuardian](https://dev.to/gitguardian/the-state-of-secrets-sprawl-2026-ai-service-leaks-surge-81-and-29m-secrets-hit-public-github-2bgj)).

The same step should dissect the command the learner wants to run, `npx --yes rea-agents@latest setup`. It downloads the newest published version, skips the confirmation prompt, and runs that package with the learner's user permissions ([npm docs](https://docs.npmjs.com/cli/v11/commands/npx)). `@latest` and `--yes` remove the two safeguards that a pinned version and a prompt provide. In September 2025 a phished maintainer's credentials pushed malicious updates to 18 popular packages, including chalk and debug, then the Shai-Hulud worm spread ([AWS Security Blog](https://aws.amazon.com/blogs/security/defending-against-supply-chain-attacks-like-chalk-debug-and-the-shai-hulud-worm)). A separate study found 19.7% of AI code samples named at least one non-existent package ([Cloud Security Alliance](https://labs.cloudsecurityalliance.org/research/csa-research-note-slopsquatting-ai-supply-chain-20260419/)). REA's own docs say persistent registrations should use "one exact package version" ([REA installation docs](https://github.com/morluto/rea/blob/main/docs/installation.md)). Free resources: MDN's JSON page, GitHub's one-hour "Introduction to GitHub" course, the Oh My Git! game, and the MCP local-server guide, which doubles as a JSON, npx and env-var lab ([GitHub Skills](https://github.com/skills/introduction-to-github); [Oh My Git!](https://ohmygit.org/)).

## Steps 3 and 4: tools, MCP, skills, plugins, Higgsfield and the context cost

**Step 3: tools.** The model never runs anything. The app sends a list of tool names, descriptions and JSON-Schema parameters. The model replies with a structured call and stops, then the app (or, for server tools, the provider) runs it and returns the result as more input ([Anthropic tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)). OpenAI states that function definitions "count against the model's context limit and are billed as input tokens" ([OpenAI](https://developers.openai.com/api/docs/guides/function-calling)). Code can therefore run in three places: on the learner's PC (bash, local MCP servers like REA), on the provider's servers (server tools, claude.ai connectors), or on a third party's servers (remote MCP like Higgsfield). The Hugging Face Agents Course Unit 1 is theory-focused though the course lists basic Python as a prerequisite ([HF Agents](https://huggingface.co/learn/agents-course/unit0/introduction)).

**Step 4: MCP and its neighbors.** MCP is an open JSON-RPC standard, announced November 2024, donated to the Linux Foundation's Agentic AI Foundation in December 2025 (per secondary sources), and now at spec revision **2026-07-28**, which made the protocol stateless and deprecated Sampling, Roots and Logging, so 2025 tutorials describe older behavior ([MCP changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog); [IT Brief](https://itbrief.co.uk/story/anthropic-donates-mcp-to-new-agentic-ai-foundation)). MCP does not change how models call tools. It standardizes how apps get tools from outside programs. A connector is Claude's product name for a (remote) MCP server linked to an account, and claude.ai calls it from Anthropic's cloud, so a local npx server cannot be a claude.ai connector ([Claude Help](https://support.claude.com/en/articles/11175166-about-custom-connectors-using-remote-mcp)). Skills are instruction packs whose name and description stay loaded until used, plugins are bundles of skills, subagents, hooks and MCP servers, and in Claude Code slash commands have merged into skills ([Claude Code skills](https://code.claude.com/docs/en/skills); [plugins](https://code.claude.com/docs/en/plugins)). The same server works in every app but the config differs: JSON `mcpServers` for Claude Code and LM Studio, TOML `[mcp_servers]` for Codex, and `context_servers` for Zed (the Zed detail comes from third-party sources) ([Codex docs](https://learn.chatgpt.com/docs/extend/mcp?surface=cli); [LM Studio](https://lmstudio.ai/docs/app/mcp)).

Higgsfield is a remote server at `https://mcp.higgsfield.ai/mcp` with OAuth and no API key. Every MCP generation costs credits at standard rates "regardless of plan", the unlimited and free generations apply only on the web app, and "you are responsible for anything an agent generates through your account" ([Higgsfield Help](https://higgsfield.ai/creator-hub/help-center/mcp-cli/what-is-higgsfield-mcp)). Safe habits inferred from this: never choose "Always allow" on generation tools, check the credit balance first, and disconnect the server when not generating. Higgsfield itself is mostly an aggregator over third-party models (Kling, Veo, Sora, Seedance, Wan) adding routing, presets and character consistency, and the notes found one review wrongly calling Nano Banana a Higgsfield model when it is Google's ([Higgsfield Help Center](https://higgsfield.ai/creator-hub/help-center/ai-models/which-ai-model-should-i-use)). The related misconception is that image and video models generate pixel by pixel. Most use diffusion: start from noise and denoise repeatedly in a compressed latent space, steered by text ([Rombach et al.](https://arxiv.org/abs/2112.10752)). Autoregressive image generation does exist, as in GPT-4o, but its full architecture is unpublished.

The interference problem is where this learner's setup is most exposed. Anthropic says tool selection degrades past **30 to 50 tools**, OpenAI suggests fewer than 20, and a typical five-server setup can consume about 55k tokens of definitions ([Anthropic tool search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool); [OpenAI](https://developers.openai.com/api/docs/guides/function-calling)). Claude Code defers MCP tools by default via tool search, while Codex offers `enabled_tools` allow lists, and LM Studio warns that servers built for cloud models "may use excessive tokens" on local ones ([Claude Code MCP docs](https://code.claude.com/docs/en/mcp)). The rule for the learner is to enable REA only for RE sessions and Higgsfield only for media sessions. On security, a tool description is text the model trusts, so hidden instructions in it are "tool poisoning", hidden instructions in results are indirect prompt injection, and a server can change its definitions after approval ("rug pull"). OWASP now publishes an MCP Top 10 in beta ([OWASP](https://owasp.org/www-project-mcp-top-10/); [Simon Willison](https://simonwillison.net/2025/Apr/9/mcp-prompt-injection/)). A teachable rule is not to give one agent session private data, untrusted content and a way to send data out all at once. Free resources: the MCP intro and "Connect to local servers" guide, MCP security best practices (linked but not read by the notes), Anthropic's Agent Skills and Subagents courses, and the Hugging Face Context Course (which assumes Python and an installed code agent) ([Hugging Face](https://huggingface.co/learn/context-course)).

## Steps 5 to 7: memory and RAG, how models are made, and what the RX 580 can run

**Step 5: memory and RAG.** App memory is saved text pasted back into the prompt. Odysseus stores facts in `memory.json` and retrieves up to eight by Jaccard word overlap with no embeddings, so "my pet's name" may not retrieve "dog named Biscuit" ([Odysseus memory source](https://raw.githubusercontent.com/pewdiepie-archdaemon/odysseus/main/src/memory.py)). Claude Code loads CLAUDE.md and the first 200 lines or 25 KB of MEMORY.md each session ([Claude Code docs](https://code.claude.com/docs/en/how-claude-code-works)). RAG means chunking documents, embedding them as vectors, retrieving the closest chunks (often with BM25 keyword search) and pasting them in. Anthropic reports retrieval failures falling from 5.7% to 1.9% with contextual embeddings, contextual BM25 and reranking, and says to skip RAG for knowledge bases under about 200,000 tokens ([Anthropic](https://www.anthropic.com/news/contextual-retrieval)). Long context is not free: Anthropic calls the degradation "context rot" ([Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). A good experiment is to edit a line in `memory.json` and watch the next chat change, proving memory is not in the weights.

**Step 6: how models are made.** Pretraining (next-token prediction over trillions of tokens), supervised fine-tuning, preference tuning (RLHF, DPO, or AI feedback as in Constitutional AI), then reasoning RL on verifiable answers. In DeepSeek-R1-Zero, pure RL with rule-based rewards lifted AIME 2024 from **15.6% to 71.0%** with no supervised step ([DeepSeek-R1 paper](https://arxiv.org/html/2501.12948v1)). Distillation means training a smaller student on a teacher's outputs, and the R1-Distill models are Qwen and Llama students trained on about 800k R1 outputs, not shrunken R1s. The 2026 controversy concerns using a competitor's model as teacher through fraudulent accounts, which Anthropic alleged against DeepSeek, Moonshot and MiniMax ([Anthropic](https://www.anthropic.com/research/detecting-and-preventing-distillation-attacks)). The "$294K" R1 cost covers one final run and excludes the base model and experiments. Fine-tuning changes weights, but with LoRA the base stays frozen and a small adapter is learned. The RX 580 cannot do this: it is absent from Unsloth's AMD support list ([Unsloth](https://unsloth.ai/docs/basics/amd)), so use a free Colab T4, whose current limits the notes did not verify. Abliteration removes a single "refusal direction" from the weights ([Arditi et al.](https://arxiv.org/abs/2406.11717)). Measured side effects vary: MMLU barely moves, but GSM8K math fell by as much as 18.8 points with one tool, and a July 2026 preprint found abliterated Gemma and Qwen models more optimistic even on tasks with no refusals ([Young](https://arxiv.org/abs/2512.13655); [arXiv 2607.17427](https://arxiv.org/html/2607.17427)). Free resources: Karpathy's "Deep Dive into LLMs like ChatGPT" (about 3.5 hours), 3Blue1Brown chapters 5 and 6 (which review vectors and softmax), and the in-browser Transformer Explainer ([Transformer Explainer](https://poloclub.github.io/transformer-explainer/)).

**Step 7: local internals on this exact machine.** On Windows the RX 580 uses LM Studio's Vulkan llama.cpp runtime. AMD's HIP SDK list for Windows excludes Polaris and even RDNA2, so ROCm is not an option ([AMD](https://rocm.docs.amd.com/projects/install-on-windows/en/latest/reference/system-requirements.html)). The community llama.cpp Vulkan scoreboard gives the RX 580 **258 tokens/s prompt processing and 39 tokens/s generation** on Llama 2 7B Q4_0, against 1,816 and 76 for an RTX 3060 ([llama.cpp #10879](https://github.com/ggml-org/llama.cpp/discussions/10879)). Generation is memory-bandwidth-bound (256 GB/s), prompt processing is compute-bound, which is why the RX 580 is about half an RTX 3060 at chat speed but roughly seven times slower at reading long prompts. The notes' own arithmetic (not a measurement) puts a 4,000-token uncached prompt at about 16 seconds before the first token, which matters because Odysseus prompts are long. The Ryzen 5 2600 has no integrated graphics, so Windows and the browser also use VRAM, leaving roughly 7 to 7.5 GB.

For quantization, the llama.cpp README measures Llama-3.1-8B at 4.58 GiB for Q4_K_M versus 7.95 GiB for Q8_0, and on Llama 3 8B Q4_K_M picks the same top token as full precision **91.9%** of the time versus 97.7% for Q8_0 ([llama.cpp quantize](https://github.com/ggml-org/llama.cpp/blob/master/tools/quantize/README.md); [perplexity](https://github.com/ggml-org/llama.cpp/blob/master/tools/perplexity/README.md)). Q8_0 of an 8B model does not realistically fit. Model picks, from the official model cards and 2026 roundups: Qwen3.5-9B (Apache 2.0, BFCL-V4 66.1) and Gemma 4 E4B (Apache 2.0, native tool use) fit fully at Q4 ([Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B); [Gemma 4 E4B](https://huggingface.co/google/gemma-4-E4B-it)). Mixture-of-experts models such as Qwen3-30B-A3B (30.5B total, 3.3B active) and gpt-oss-20b must still be stored in full, so they need partial offload into the 16 GB of RAM via LM Studio's "Force Model Expert Weights onto CPU" toggle ([LM Studio 0.3.23](https://www.lmstudio.ai/blog/lmstudio-v0.3.23)). Generation from system RAM is much slower than from VRAM, so a model that spills slightly feels far worse than one that fits. A starting profile is the Vulkan runtime, full GPU offload, 8K context, flash attention tested on and off, thinking mode off for speed, and a non-abliterated model for tool use. The GGUF format bundles quantized weights with tokenizer and template metadata, and safetensors is the tensor-only original. "Open weights" differs from OSI "open source": Qwen, Gemma 4 and gpt-oss use Apache 2.0, while Llama's license adds a 700-million-user cap and naming rules ([Llama 3.1 license](https://github.com/meta-llama/llama-models/blob/main/models/llama3_1/LICENSE)). Odysseus itself is AGPL-3.0-or-later software per its repository.

## Step 8: reverse engineering and REA, on practice targets first

REA (`rea-agents`, MIT) is a local MCP server and CLI, and the README says "Reverse engineer anything with agents" ([REA README](https://github.com/morluto/rea)). Requirements: Node 22.19+, 24.11+ or 26+, and for native binaries Ghidra 12.1.x with JDK 21 or newer (Windows x64 support is "experimental"), and for APKs headless JADX plus a full JDK ([REA installation docs](https://github.com/morluto/rea/blob/main/docs/installation.md)). Static JavaScript and .NET analysis need no native engine, so they are the easiest first lane on Windows (an inference). REA's disclaimer allows CTFs and education but forbids defeating DRM, license checks and anti-cheat, making game cheats, or bypassing authentication, and warns that authorization to inspect "does not necessarily authorize execution" ([REA DISCLAIMER](https://raw.githubusercontent.com/morluto/rea/main/DISCLAIMER.md)). Runtime capture runs targets with the user's permissions, and REA marks foreign-code tools `destructiveHint: true` ([REA contracts](https://github.com/morluto/rea/blob/main/docs/mcp-contracts.md)). Because tool results go to the model provider, decompiled code from a target is sent to Claude or OpenAI unless a local model is used.

The legal picture is narrow and US-specific. DMCA exceptions for interoperability and security testing and the 2024 exemptions for good-faith security research and abandoned online games do not shield against CFAA or contract claims, and the security-research exemption says it is not a safe harbor ([37 CFR 201.40](https://www.law.cornell.edu/cfr/text/37/201.40)). Game EULAs commonly ban reverse engineering, and the clause most often enforced is anti-cheat and cheating rules, not the EULA text. The notes found no teen-specific legal guidance and nothing on non-US law, so this is information, not legal advice. The safe path: CyLab Security Academy (picoCTF's new name since May 2026; free, for middle school through adult, with a Reverse Engineering domain), then the official Ghidra Beginner class, then crackmes.one difficulty-1 binaries in a snapshotted VM with the network off, then REA against those same files with its filesystem scope limited to the challenge folder ([CyLab Academy](https://cylabacademy.org/); [crackmes.one FAQ](https://crackmes.one/faq)). Learn manual RE first so the learner can judge REA's output, which Anthropic's AI Fluency framework calls Discernment ([Anthropic AI Fluency](https://www-cdn.anthropic.com/b383cf6baddbfc72fdf8b0ed533a518e2872d531.pdf)). Register REA with an exact version (for example `rea-agents@6.4.0`, version-dependent) after reading `rea setup`'s previewed changes, not with `--yes @latest`. Do not expect an 8B local model to drive 126 tools: this is inferred from the 30 to 50 tool threshold, LM Studio's token warning, and the finding that Qwen3-4B scored only 35.25% on multi-turn function-calling ([TinyLLM](https://arxiv.org/pdf/2511.22138)); no one tested REA with a local model. Better options are a cloud model, the REA CLI run directly with pasted output, or REA's compact schema profile as an experiment. "Modding things you own" is the gray zone: owning a copy does not override the license, so stay with open-source apps, the learner's own projects, and offline single-player games whose EULA permits modding.

## Is learning to code worth it? A light, read-and-verify version

The evidence is mixed and mostly opinion. BLS projects 10% growth for software developers from 2025 to 2035, with a median pay of $135,980 ([BLS](https://www.bls.gov/ooh/computer-and-information-technology/software-developers.htm)), but a Stanford payroll study found a 16% relative employment decline for ages 22 to 25 in the most AI-exposed jobs, correlational and relative ([Stanford DEL](https://digitaleconomy.stanford.edu/news/canaries-interest-rates-and-timinga-more-on-recent-drivers-of-employment-changes-for-young-workers)). Jensen Huang said in 2024 that programming need not be learned, while Andrew Ng called skipping coding "the worst career advice ever given" and GitHub's then-CEO said every child should learn it ([Tom's Hardware](https://www.tomshardware.com/tech-industry/artificial-intelligence/jensen-huang-advises-against-learning-to-code-leave-it-up-to-ai); [OfficeChai](https://officechai.com/ai/not-learning-to-code-because-of-ai-is-the-worst-career-advice-ever-andrew-ng/)). The job data matters mainly to someone seeking an entry-level software job, which is not this learner's stated goal.

What current agent practice demands is the deciding evidence. Anthropic and OpenAI docs both tell users to plan first, give the agent a way to verify (tests, builds, screenshots) and review before accepting ([Claude Code best practices](https://code.claude.com/docs/en/best-practices); [OpenAI Codex](https://learn.chatgpt.com/guides/best-practices)). Veracode found about 45% of AI-generated code tasks had security flaws, and Stanford found assistant users wrote less secure code while feeling more confident ([Veracode](https://www.veracode.com/press-release/ai-generated-code-poses-major-security-risks-in-nearly-half-of-all-development-tasks-veracode-research-reveals/); [arXiv 2211.03622](https://arxiv.org/html/2211.03622v3)). METR's 2025 trial found experienced developers 19% slower while believing they were 20% faster, though the 2026 follow-up was inconclusive ([METR](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)). Anthropic's own randomized trial found AI-assisted learners scored 17% lower on a quiz, but those who asked conceptual follow-up questions retained more than those who delegated generation ([Anthropic](https://www.anthropic.com/research/AI-assistance-coding-skills)). The recommendation is therefore: skip syntax mastery, but spend a few weeks on one language (CS50P is the likely fit; CS50x starts in C and is large) aimed at reading code, errors and diffs, plus tests and secret hygiene. Adopt Simon Willison's rule of not committing code you could not explain, and when an agent writes something, ask why and how, not just "make it work" ([Simon Willison](https://simonwillison.net/2025/Mar/19/vibe-coding/)). Vibe coding is defensible for throwaway projects and not for anything holding other people's data, money or credentials. No rigorous study covers non-programmers building with agents or hitting a ceiling, so this is judgment from adjacent evidence.

## Conclusion

The notes change the shape of the plan more than its content. The learner does not need to learn more things so much as learn them in the order that removes blockers: JSON, npx and secrets before MCP, weights before quantization, and practice binaries before REA. The most dangerous gaps are practical, not conceptual: believing `.env` encrypts, running `npx --yes @latest` on an unvetted package, clicking "Always allow" on a paid or execution-capable tool, and running unknown binaries outside a VM. All of these are fixed by habits taught in the first afternoon.

Two things remain open that only the learner can settle. They should check REA's npm page and repository, and run `rea doctor --json` to see the real tool count, before registering it. They should also produce their own Windows LM Studio tokens-per-second readout for Qwen3.5-9B and Gemma 4 E4B, which would replace the scoreboard-based estimates here with a measured number and fill the biggest hole in the hardware evidence.
