# Networked AI Company

A lean Paperclip company package for a comment-driven AI organization. Content Creation and Business are the primary production lanes. The CEO and Coding Lead maintain the workflow, while a small Coding team experiments with verified autonomy.

## Org structure

- CEO — company priorities, strategy, resource allocation, and operating health.
- Coding Lead — translates intent into technical execution and owns the engineering workflow.
- Coder One — primary implementation and debugging.
- Coder Two — independent implementation and comparison.
- PStack Coder — applies a rigorous engineering style as one independent coding perspective.
- Reviewer — event-driven peer review and challenge, not a mandatory QA gate.
- Tester — focused runtime and behavioral verification for risky or user-facing work.
- Content Lead — primary content planning and production.
- Business Lead — monetization, efficiency, opportunities, and operations.
- Research Lead — evidence gathering and analysis across branches.
- Trading Lead — trading objectives, risk, strategy, and team coordination.
- Trading Research — specialized market, dataset, and statistical validation.
- Game Coding Lead — side-project prototypes and game development studies.
- Memory Lead — company-wide memory standards and cross-branch synthesis.
- Coding, Business, Trading, Research, Content, and Game Memory — branch-specific retrieval and durable context.

## Workflow

Work has one accountable owner but does not move through a fixed pipeline. Agents ask Coding, Research, Memory, or another relevant peer directly when that contribution materially improves the result. The CEO and Coding Lead use the delegation-design rubric before splitting work or proposing another durable agent. Trading operates as a specialized team while borrowing the main Coding organization for technical infrastructure. Experiments record attempts, failures, interventions, and evidence for Research and Memory.

## Import

```sh
paperclipai company import ./companies/networked-ai-company --target new
```

This package follows the [Agent Companies specification](https://agentcompanies.io/specification) and is intended for [Paperclip](https://github.com/paperclipai/paperclip).

## Shared support and activation

All roles use the comment-verification skill for direct peer help, task ownership, economical model use, shared memory, and experiment boundaries. Memory Lead and its branch specialists serve the network; agents can also record and retrieve project knowledge directly. Game Coding remains within the Coding Lead's architecture ownership.

These files define an importable operating policy. Editing them does not update a running company, select model adapters, provision memory storage, or activate schedules. Import or reconcile them with the intended company after review. Bind existing project/company knowledge facilities and configure available models, budgets, and one or two nightly experiment windows before enabling scheduled work. Do not import a duplicate company merely to update existing agents.
